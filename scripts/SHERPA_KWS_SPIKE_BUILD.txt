Sherpa-ONNX KWS WASM spike (Voyagr)
===================================

There is NO official prebuilt WASM KWS tarball (see GitHub sherpa-onnx issue #3112).
You must build the WASM bundle once (Emscripten), then copy the install output here.

1) Clone sherpa-onnx and install Emscripten. Upstream docs suggest a version **in the 3.1.48
   – 3.1.64** range (e.g. 3.1.53); 3.1.70+ is called out as problematic in official sherpa docs.

2) Prepare wasm/kws/assets/ with ONNX + tokens + en.phone + keywords.txt
   - Easiest: run scripts/prepare-sherpa-kws-wasm-assets.sh from sherpa-onnx repo root.
     It downloads sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20 and stages the files
     under epoch-12 filenames — which is what upstream wasm/kws/CMakeLists.txt
     bakes into its --preload-file list, and therefore what ends up inside the
     generated sherpa-onnx-wasm-kws-main.data virtual FS.
   - Voyagr's runtime (static/js/sherpa-onnx-kws-spike.js + sherpa-kws-map-runtime.js)
     asks the virtual FS for those same epoch-12 filenames. Changing one side
     without the other leaves you with "transducer ... does not exist" + a silent
     dead recogniser (the C API logs "Errors in config!" and returns NULL).

3) **Emscripten:** you only need one clone of `emsdk` (e.g. `/root/emsdk`). If `git clone` says
   the path already exists, `cd` there and run `./emsdk install 3.1.53 && ./emsdk activate 3.1.53`
   then `source /root/emsdk/emsdk_env.sh` in the same shell before `./build-wasm-simd-kws.sh`.
   A large one-time download is normal; wait for it to finish.

4) **Required for English phone+ppinyin KWS (e.g. zh-en 3M model + en.phone):**
   The stock `GetKeywordSpotterConfig` in `sherpa-onnx/c-api/c-api.cc` does not copy
   `modeling_unit` / `bpe_vocab` from the C struct (the online *recognizer* path does).
   Symptoms: stderr shows `modeling_unit="cjkchar"` no matter what the JS config says,
   then opaque WASM exceptions. Apply Voyagr’s c-api patch, then build. If the link step
   fails on `std::filesystem` in `libonnxruntime.a`, use troubleshooting (a–d) below; (d) is
   a small `wasm/kws/CMakeLists.txt` patch that forces full `libc++` for wasm-ld.

   **Run this from the sherpa-onnx *clone* root** (the directory that contains
   `build-wasm-simd-kws.sh` and the nested `sherpa-onnx/c-api/c-api.cc` path), **not** from
   `/opt/voyagr`. Example (adjust clone path, often `~/sherpa-onnx` or `/root/sherpa-onnx`):

     cd /root/sherpa-onnx
     patch -p1 < /opt/voyagr/scripts/patches/sherpa-onnx-kws-GetKeywordSpotterConfig-modeling.patch

   Equivalent in one line:

     patch -p1 -d /root/sherpa-onnx < /opt/voyagr/scripts/patches/sherpa-onnx-kws-GetKeywordSpotterConfig-modeling.patch

   Or from the clone: `git apply /opt/voyagr/scripts/patches/...` (only if you used git; prefer `patch` for vendor trees.)

   If a previous attempt failed, restore the C++ file and remove rejects before retrying, e.g.:
   `cd /root/sherpa-onnx && git checkout -- sherpa-onnx/c-api/c-api.cc` (and delete `c-api.cc.rej` if present), then `git pull` in `/opt/voyagr` to get the latest patch hunk, then re-run `patch -p1 < ...` from the sherpa root.

   If the build script says **Please install emscripten first**, install and activate 3.1.53 (script prints commands), `source` the env, then re-run `build-wasm-simd-kws.sh` in the same shell.

   The patch is generated with `python3 /opt/voyagr/scripts/patches/gen_sherpa_kws_patch.py` so
   each context line has the required one-column diff prefix (without it, the C++ line is one
   space too short and `patch` reports `Hunk #1 FAILED at 1001`).

   If the patch does not apply cleanly (line numbers),
   add the same block manually right after
   `spotter_config.model_config.debug = config->model_config.debug;` in
   `GetKeywordSpotterConfig` — copy the `modeling_unit` / `bpe_vocab` block from
   `GetOnlineRecognizerConfig` in the same file.

5) From sherpa-onnx repo root:
     ./build-wasm-simd-kws.sh

6) Copy build output into Voyagr (paths relative to Voyagr repo root):
     cp -a build-wasm-simd-kws/install/bin/wasm/* static/vendor/sherpa-kws/wasm/

7) Open in browser (HTTPS):
     /static/sherpa-kws-spike.html

Troubleshooting — link step: `undefined symbol: std::__2::filesystem::path::...`
----------------------------------------------------------------
The CMake build downloads a **prebuilt** `libonnxruntime.a` (see
`cmake/onnxruntime-wasm-simd.cmake` in the sherpa-onnx tree). If that archive was built with a
**different** Emscripten / libc++ than the one you use to link the final
`sherpa-onnx-wasm-kws-main.wasm`, the linker can fail with `std::filesystem` / `__parent_path`
errors. This is a **toolchain mismatch**, not a Voyagr bug.

**Try in order (use full paths on your server):**

a) **Align sherpa-onnx and ORT** — `git -C /root/sherpa-onnx pull`, then **wipe the build
   tree** so FetchContent re-downloads the ORT zip that matches your current CMake:
     rm -rf /root/sherpa-onnx/build-wasm-simd-kws
   Then `source /root/emsdk/emsdk_env.sh` and run
   `cd /root/sherpa-onnx && ./build-wasm-simd-kws.sh`.

b) **Use another supported emsdk** in the 3.1.x line. After (a), try **3.1.48** (the version
   shown in [sherpa’s wasm emscripten doc](https://k2-fsa.github.io/sherpa/onnx/wasm/install-emscripten.html)),
   then `3.1.53` / `3.1.64` (all ≤3.1.64 per upstream). In `/root/emsdk` run
   `./emsdk install VERSION && ./emsdk activate VERSION`, `source emsdk_env.sh`, wipe
   `build-wasm-simd-kws`, and rebuild.

c) If it still fails, check which ORT version your `cmake/onnxruntime-wasm-simd.cmake` pins;
   older sherpa checkouts may pull an ORT build that no longer matches a given emsdk. Either
   move forward with a current **sherpa-onnx** `main` or match versions described in
   [sherpa wasm install](https://k2-fsa.github.io/sherpa/onnx/wasm/install-emscripten.html)
   and the [k2-fsa/sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) issue tracker for WASM
   + ONNXRuntime.

d) **Voyagr CMake link patch (fixes `__parent_path` / `__filename` from `libonnxruntime.a`):**
   The failure is usually because em++ links **`-lc++-noexcept`** by default, while the
   prebuilt ORT needs **`std::filesystem` from full `libc++`**. The patch enables
   **`-fexceptions`** and **`-Wl,--whole-archive -lc++ -lc++abi`**. The patch file must
   exist on the server (e.g. `git pull` the Voyagr app under `/opt/voyagr` so
   `scripts/patches/sherpa-onnx-wasm-kws-link-wholearchive-libcxx.patch` is present).

   From the sherpa-onnx **clone root**, reset CMake if needed, then:

     git checkout -- wasm/kws/CMakeLists.txt
     patch -p1 < /opt/voyagr/scripts/patches/sherpa-onnx-wasm-kws-link-wholearchive-libcxx.patch

   Wipe the build directory and run `./build-wasm-simd-kws.sh` again. If the patch was
   already applied, `patch` may complain — use a manual edit matching that `.patch` file.

The previous failed link still leaves an **old** `install/bin/wasm/` — do not `cp` it to
production until `make` completes without error.

Keyword line for "Hey Sat Nav" was generated with sherpa-onnx-cli text2token using
tokens-type phone+ppinyin and en.phone from the zh-en model (see static/vendor/sherpa-kws/spike-config/).
Regenerate after changing the phrase:
  pip install sherpa-onnx sentencepiece pypinyin
  sherpa-onnx-cli text2token --tokens <model>/tokens.txt --tokens-type phone+ppinyin \
    --lexicon <model>/en.phone keywords_raw.txt keywords.txt
