Mandatory polygon membership has appreciably greater cost than numeric-only endpoint checks because it scans the existing8301-member local area inventory; request-local per-coordinate memoization shares results across alternatives/legs. Do not treat the small numerical-only overhead as representative of large journeys or all hazards. No added provider/network calls, graph search, retry loop or background work is introduced.

Existing browser cancellation/latest-response rejection remains unchanged.

Bounded production log fields include server-generated request correlation, allowlisted provider identity, displacement **bucket** (within2m /2–25 /25–100 /over100 /unknown), origin status, local evidence availability, quarantine flag, transition=false, alternative presence and shared stage duration. No raw GPS, exact displacement, native response, request/custom model, personal history or raw error text is added to telemetry. Exact displacement and requested coordinates remain private route-response data needed for the UI/cache contract. Existing selected endpoint and reroute event-body console dumps on the touched browser paths were removed.

`origin_fallback_attempted=false` specifically describes this validation stage: no new provider request is launched by assessment. Earlier provider fallback is separately observable through existing provider-stage logs/timing; do not infer an earlier fallback from alternative presence or attribute another request's logs without the request ID.
