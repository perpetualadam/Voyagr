## Policy

Provider-independent validation compares the **original request**, not cached/provider start labels, with the first and last vertices of the actual returned route, in metres using the existing great-circle distance function. The requested origin is retained in the private route assessment, not production telemetry. Native GraphHopper snapped waypoints, when present, must decode and agree with returned geometry; missing native snaps use actual route geometry with explicit evidence limitation. Malformed, contradictory and degenerate snaps are quarantined. A zero-length route cannot be a connector.

The2m numerical continuity tolerance derives from p5 polyline quantization: maximum lat/lon cell rounding is below1.6m even at the equator. It is a conservative serialization allowance, **not a road-access/search radius or guarantee of same road**. Boundary tests cover1.999/2.001m. The existing spherical distance approximation is appropriate to metre-scale screening; this is not survey/ellipsoidal accuracy. Normal coordinate rounding is distinguished from larger unresolved snapping. GPS accuracy in(0,150]m follows the existing fix ceiling; fresh matching browser fixes only are attached. A displacement within reported GPS uncertainty gets a different reason but **no larger permission radius**. Client accuracy cannot authorise a road transition.

Routes displaced beyond numerical continuity, including ordinary5m GPS-related snaps, remain quarantined until road-connected legality can be verified. This intentionally conservative compatibility cost is explicit: the implementation has no verified connector/exit mechanism. Same-road labels, proximity, one-way/carriageway labels and cached `transition_verified` claims cannot override it. Even coincident geometry does not establish road/lane identity; existing independent road-association/GPS progress safeguards remain required.

Mandatory local camera/CAZ geometry is checked with union semantics, holes and a numerical boundary band (~millimetres). Inside or boundary at either endpoint blocks navigation. Missing/malformed applicable geometry is UNKNOWN and blocked; outside local polygons never claims worldwide completeness/current hazard absence. The original invalid MultiPolygon aggregation is evaluated as its member polygon union, not asserted valid or imported by the engine. Existing independent hazard coverage, age, direction and mandatory requirements still govern eligibility. Dynamic OSM polygon provenance not exposed at the assessment boundary remains an evidence limitation, handled by existing hazard compliance gates; no empty-road assumption is introduced.

Each multi-stop leg is bound to the **current request's** start/ordered visits/end; cached `from`/`to` cannot validate themselves. Missing/unbound legs block. Existing full-geometry stitching and checksum checks remain. Cache metadata is recomputed per HTTP request, without mutating cached objects. Browser legacy/missing/stale/offline origin assessments require online recalculation, including preference mode. Selection carries each route's own assessment; unresolved origin cannot be confirmed manually. Fresh available raw GPS differing from the assessed request also blocks reuse. When fresh GPS is unavailable, existing uncertain-position progress/voice pausing still applies; physical-device lifecycle acceptance remains NOT_TESTED.

## Safe exit

No automatic safe-exit exception is implemented or accepted. Starting within a mandatory excluded area yields UNRESOLVED, not SATISFIED. A legal transition needs independently reviewed directed graph edges, lawful turns/access, actual origin-road association and explicit policy for unavoidable restricted initial travel. Straight-line segments, zero-length snapped routes and requested hard-zero acceptance do not supply this evidence. No mandatory restriction is removed. User confirmation cannot authorise a quarantined start.

Eligible GraphHopper remains first, irrespective of nearby-marker counts. An eligible Valhalla/OSRM alternative can precede an origin-ineligible route under the same gates. Assessment launches no connector/fallback requests: it only evaluates already returned alternatives. Existing provider fallback remains shared-budget controlled. If none is eligible, previews may be retained for inspection with UNRESOLVED state; navigation is blocked.
