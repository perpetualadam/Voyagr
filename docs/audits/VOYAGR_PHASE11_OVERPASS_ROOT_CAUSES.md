## Diagnostic change and residual limitations

Only observability changed: request/operation IDs, monotonic timing, endpoint slot/status/attempt, query-kind and budget-presence events, plus diagnostic context propagation into the **existing** viewport tasks. The misleading viewport helper docstring was corrected. One existing unexpected-exception log now reports type instead of arbitrary exception text; exception return/retry semantics remain unchanged. No cache, retry, endpoint preference, thread-count, mandatory compliance, GraphHopper model, routing gate or infrastructure behavior was changed.

On new logs, join request_id, then operation, PID/thread and elapsed_ms. A query started on an executor thread has `budget_present=false` even if its initiating browser action also had a routing request. `response_ready` is an application boundary, not proof of delivery. Old logs cannot be retroactively assigned IDs. Direct requests and existing provider log lines do not yet have operation-level trace coverage. See the operator report before claiming a production root cause.

## Phase 11B recommendations, in order

1. Reject malformed/incomplete Overpass success bodies: require an object and list of valid elements, treat runtime remarks as incomplete/failed, never cache errors as empty complete coverage. Preserve uncertainty and mandatory navigation gates; test partial output, valid empty results and provenance.
2. Propagate request deadlines immediately through helper and hazard preparation. Check before cache return when serving a deadline-bound route. Keep Phase10 outer checks/late-result rejection and GraphHopper-first policy. Distinguish deadline, provider timeout and query/runtime errors.
3. Give viewport tasks their own bounded monotonic work budgets and bounded admission. Cancel queued unnecessary tasks when safe; a future cancellation cannot interrupt a running request. Propagate diagnostic identity without sharing unsafe Flask context; specify cancellation semantics explicitly.
4. Define reviewed local-first/fallback policy, recovery probing and a per-query visited set. Bound aggregate public retry exposure and remove waits with no subsequent attempt. Do not silently disable needed hazard acquisition or claim public mirrors have independent capacity.
5. Unify active direct lane/speed/search paths behind explicit endpoint/deadline policy. Preserve conservative lane/speed evidence semantics and user preferences. Add safe bounded response streaming/caps with incomplete-coverage handling.
6. Coalesce identical concurrent queries with bounded waiter semantics; include query identity, provider/source freshness and exact relevant bounds in cache design. Avoid a global lock around network work or coordinate-bearing diagnostic hashes. Bound cache size and process-level concurrency; test multiworker behavior before choosing shared infrastructure.
7. After operator evidence, decide whether query area/output or installed resources need remediation. Measure bytes/elements, query kind, stage duration and active/queued tasks separately; tune no production resources from synthetic fixtures alone. Sanitize legacy coordinate/endpoint/exception logs before sharing diagnostics.

Acceptance remains blocked on correlating production request identities, identifying the actual502/invalid-response generator, verifying installed coverage/freshness and demonstrating bounded latency under real workload. Automated test success is not production GO.
