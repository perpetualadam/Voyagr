## Version 1 contract

`voyagr/utils/road_matching.py` and `static/js/modules/navigation/road-matching.js` implement the same source-linked policy, tested with the same 20 versioned scenarios. Fields include optional source segment ID, OSM way ID, namespaced graph edge ID/provider, optional carriageway ID, route/source segment indices, forward/backward source direction, matched coordinate, observation distance/accuracy, heading difference, LOW/HIGH/NONE confidence, source/revision/acquisition time, evidence status, route identity/generation, fix timestamp and attribute permission. Missing IDs remain null; local geometry indices are not stable road identifiers.

States are VERIFIED_AGAINST_SOURCE, PROBABLE, AMBIGUOUS, UNMATCHED and STALE. GPS association only emits PROBABLE, never VERIFIED_AGAINST_SOURCE. The latter is used by the source-topology validator for a graph assertion, not physical vehicle position. Source-link verification means identifiers belong to the supplied source; it is not survey/legal authority.

A bounded geographic grid generates nearby segment candidates. Distance/accuracy, qualified heading, one-way direction, previous road, connected source nodes, directed turn restrictions, elapsed time and travel distance are combined. Multiple road/direction hypotheses stay AMBIGUOUS; nearest distance and active-route preference never eliminate a plausible parallel road. Bridges/tunnels without distinguishing observations remain ambiguous. Conflicting graph-edge-to-way bindings invalidate context. Low-speed heading is ignored; no lane-level position inferred.

Policy: fix age ≤15 s / future ≤1 s, accuracy ≤35 m; heading requires speed 3–80 m/s, accuracy ≤15 m and optional heading accuracy ≤30°. Candidate corridor is max(12 m, accuracy), heading tolerance 45°. Fresh continuity requires two fixes within 15 s and one source/route generation. Displacement/network path budget is max(10 m/s, observed speed) × elapsed +2×accuracy +20 m. Road changes need shared source connectivity and a plausible path via that shared node; via-node no/only restrictions are checked. These are explicit conservative engineering tolerances, not calibrated statistical probabilities. Unsupported restrictions/vehicle/access context, partial/border coverage or absent stable source linkage cannot grant attributes.

Source age ceiling is 24 h; legal speeds retain Phase 6's stricter 300 s source observation limit. Source coverage must include the candidate search corridor. Per-source limits: 20,000 ways, 100,000 segments, 200,000 grid references, ≤1,000 cells per segment. Source loader limits input to 10 MiB, refuses synthetic live sources and malformed structures. Context response is capped at 1,000 ways /2 MiB and is normally a centred .01° window; source edges remain conservative.

## Shared PWA and HTTP integration

`road-match-orchestration.js` owns source context and match state. It fetches bounded local-source context at most once per 30 s, refreshes after 60 s or movement outside its inner coverage, aborts after 4 s, and rejects superseded route/vehicle responses. No per-fix network request. GPS rejection invalidates attribute authority immediately. Route compatibility is either typed MATCHED or GEOMETRY_COMPATIBLE (≤5 m source-to-route geometry and ≤45° direction, no separated competing route branches); the latter does not assert provider edge identity. Different/ambiguous available source context pauses progress and specific guidance. Supported off-route matches feed existing reroute hysteresis. Without source context, conservative Phase 6 ordinary route navigation remains; definitive road-level lanes/legal values remain unknown.

POST `/api/road-context` reads only an operator-selected `VOYAGR_ROAD_EVIDENCE_FILE`; request paths/IDs never select source data. POST `/api/road-match` recomputes from raw current/previous fixes and source geometry, ignoring client match claims. This endpoint does not prove client GPS is authentic; it prevents a claimed road ID from becoming source evidence. No location history is persisted. Bodies are bounded, endpoints rate-limited (120/min per remote address, shared Redis when configured), responses no-store and service-worker v45 prevents caching/queuing/replay for both methods. Review shared-NAT/reverse-proxy rate behaviour before deployment.

The operator confirms APIs are self-hosted on Contabo. Same-origin Flask integration and existing provider infrastructure are preserved. No production/self-hosted endpoint was probed. An approved offline extract from that infrastructure can supply fixtures; no third-party paid service or automatic fallback was introduced.
